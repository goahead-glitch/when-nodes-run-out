# 15. VM 백업 / 복원 (포터블 스냅샷)

> 📁 **원본 실행 문서** — 팀 저장소 `Incheon-soda/shoply`의 `문서/15_VM백업_복원.md`(2026-06-12)를 그대로 옮겼습니다. AMI 이전에 실제로 클러스터를 세울 때 쓰던 문서입니다.
> 최종 정리본: [`../BACKUP-RESTORE.md`](../BACKUP-RESTORE.md) qcow2 수동 백업

> 셋팅 다 끝낸 클러스터를 **qcow2 통째로 백업 → PC 보관 → 새 EC2에 풀어서 부활**.
> 재구축의 모든 고생(br_netfilter·flannel·loopback 방화벽·metrics-server·configmap IP...)을 건너뛴다.
> "서버 다운 → 재구축 1~2시간"이 "복원 몇 분"으로.

---

## 원리

VM = `/var/lib/libvirt/images/*.qcow2`(디스크) + libvirt XML(정의). **이 둘만 있으면** 어느 KVM 호스트에서든 되살린다.

```
[정상 클러스터] → 정지 → qcow2+XML 백업 → tar → PC 보관
                                              ↓ (나중에)
[새 EC2] ← virsh define+start ← qcow2+XML ← 업로드 ← PC
```

---

## ⚠️ 백업 전 필수 — VM IP 고정

복원 시 VM이 **새 IP**를 받으면 인증서·kubeconfig·etcd가 옛 IP를 가리켜 **클러스터가 깨진다.** 백업 전에 IP를 고정한다.

```bash
# 호스트 EC2 — 각 VM의 MAC 확인
for vm in k8s-master k8s-worker1 k8s-worker2 k8s-worker3; do
  echo "$vm: $(sudo virsh domiflist $vm | awk 'NR==3{print $5}')"
done

# DHCP 예약 (MAC → 고정 IP). 현재 IP 그대로 박는 걸 권장
sudo virsh net-update default add ip-dhcp-host \
  "<host mac='<master-MAC>' name='k8s-master' ip='192.168.122.51'/>" --live --config
# worker1·2·3도 각각 (현재 virsh net-dhcp-leases default 의 IP로)
```
> XML에 MAC이 보존되므로, 예약만 같이 살리면 복원해도 같은 IP를 받는다.

## 백업 (호스트 EC2 → PC)

```bash
# 1. VM 정지 (콜드 백업 — etcd 일관성 위해 필수. 켜진 채 복사 금지)
for vm in k8s-master k8s-worker1 k8s-worker2 k8s-worker3; do sudo virsh shutdown $vm; done
sudo virsh list --all        # 전부 shut off 확인 (안 꺼지면 sudo virsh destroy <vm>)

# 2. XML 정의 + 네트워크 백업
mkdir -p ~/vm-backup
for vm in k8s-master k8s-worker1 k8s-worker2 k8s-worker3; do
  sudo virsh dumpxml $vm > ~/vm-backup/$vm.xml
done
sudo virsh net-dumpxml default > ~/vm-backup/default-net.xml

# 3. qcow2 압축 복사 (30GB 할당이라도 실제 사용분만 → 용량 확 줄음)
for vm in k8s-master k8s-worker1 k8s-worker2 k8s-worker3; do
  sudo qemu-img convert -O qcow2 -c \
    /var/lib/libvirt/images/$vm.qcow2 ~/vm-backup/$vm.qcow2
done

# 4. 한 덩어리로 묶기
sudo tar czf ~/shoply-cluster.tar.gz -C ~/vm-backup .
ls -lh ~/shoply-cluster.tar.gz       # 보통 15~40GB

# 5. (백업 후 다시 쓰려면) VM 재시작
for vm in k8s-master k8s-worker1 k8s-worker2 k8s-worker3; do sudo virsh start $vm; done
```

**PC로 다운로드 (맥):**
```bash
scp -i ~/key/aws-3tier-keypair.pem \
  ubuntu@<EC2-공인IP>:~/shoply-cluster.tar.gz ~/Downloads/
```

> **용량 더 줄이기**: 백업 전 VM 안에서 `sudo apt clean && sudo journalctl --vacuum-time=1d && sudo fstrim -av` → 압축률↑.

## 복원 (새 EC2)

```bash
# 0. 새 EC2 — 중첩가상화 켜고(doc13 0단계) + KVM 설치(doc13 2단계)

# 1. PC → 새 EC2 업로드 (맥에서)
scp -i ~/key/aws-3tier-keypair.pem \
  ~/Downloads/shoply-cluster.tar.gz ubuntu@<새-EC2-공인IP>:~/

# 2. 풀고 qcow2 배치 (새 EC2에서)
mkdir -p ~/vm-backup && tar xzf ~/shoply-cluster.tar.gz -C ~/vm-backup
sudo cp ~/vm-backup/*.qcow2 /var/lib/libvirt/images/

# 3. VM 정의 + 시작 (default 네트워크는 KVM 설치 시 보통 이미 존재)
for vm in k8s-master k8s-worker1 k8s-worker2 k8s-worker3; do
  sudo virsh define ~/vm-backup/$vm.xml
  sudo virsh start $vm
done
sudo virsh list --all
sudo virsh net-dhcp-leases default     # VM들이 고정 IP로 떴는지 확인
```

→ **클러스터가 셋팅된 그대로 부활.** kubectl get nodes/pods로 확인.

## 복원 후 체크리스트

| 항목 | 확인/조치 |
|---|---|
| VM IP | `virsh net-dhcp-leases default` → 백업 때와 같은 IP인지 (고정했으면 OK) |
| 클러스터 | master에서 `kubectl get nodes` (4개 Ready), `kubectl get pods -A` |
| **호스트 IP 갱신** | 새 EC2는 새 사설IP → `prometheus.yml`·호스트 `DNAT`의 **호스트IP만** 교체 (VM 내부는 그대로) |
| DNAT 재적용 | 호스트 iptables는 새 EC2라 비어있음 → doc13 11·14단계 DNAT + FORWARD 재실행 |
| 외부 서버 | DB·Redis·모니터링·k6 EC2도 새로 떴으면 IP 갱신 (configmap·prometheus.yml) |

### DB/Redis IP 갱신 (master VM에서 — 파일 수정 없이 바로 적용)

EC2를 새로 띄워 DB/Redis 사설 IP가 바뀐 경우, repo 파일을 옮기지 말고 `kubectl patch`로 바로 반영한다.

```bash
# 1. ConfigMap 패치 (DB/Redis IP만 갱신 — 값은 매번 새 IP로 교체)
kubectl patch configmap shoply-config -n shoply --type merge -p \
  '{"data":{"POSTGRES_HOST":"<새 PostgreSQL IP>","REDIS_HOST":"<새 Redis IP>"}}'

# 2. DB/Redis 의존 서비스 재시작 (ConfigMap은 재시작해야 반영됨, frontend·gateway 제외)
kubectl rollout restart deployment user product inventory order payment -n shoply

# 3. 확인 (전부 1/1 인지)
kubectl get pods -n shoply
```

## ⚠️ 흔한 함정

1. **cloud-init ISO 참조 에러** — XML이 `*-cloud-init.iso`(cdrom)를 참조하는데 복원 시 그 파일이 없으면 `virsh start` 실패.
   → 해결: 백업한 XML에서 cdrom 디바이스(`<disk device='cdrom'>...</disk>`) 줄을 지운다 (cloud-init은 최초 1회 실행으로 이미 끝남). 또는 iso도 같이 백업.
   ```bash
   # XML에서 cdrom 블록 제거 예시 (복원 전 PC/EC2에서)
   # <disk type='file' device='cdrom'> ~ </disk> 부분 삭제 후 define
   ```
2. **켜진 채 백업** → etcd가 어중간한 상태로 복사돼 복원 시 깨짐. **반드시 정지 후.**
3. **IP 안 고정** → 복원 시 IP 바뀌어 클러스터 깨짐 (위 "IP 고정" 단계 필수).
4. **default 네트워크 대역 불일치** — 새 호스트의 libvirt default도 `192.168.122.0/24`여야 함 (기본값이라 보통 일치). 다르면 `~/vm-backup/default-net.xml`로 맞춘다.

## 복원 자동화 스크립트 (KVM 설치까지 한 방)

qcow2 복원의 유일한 번거로움은 "새 EC2에 KVM 또 깔기"다. `scripts/restore-cluster.sh`가 **디스크확장 + KVM설치 + DNS + qcow2복원 + VM정의/시작**을 한 번에 한다.

```bash
# 새 EC2(중첩가상화 켜진 인스턴스)에서
scp -i key.pem ~/Downloads/shoply-cluster.tar.gz ubuntu@<새EC2>:~/
scp -i key.pem scripts/restore-cluster.sh ubuntu@<새EC2>:~/
ssh ubuntu@<새EC2>
chmod +x restore-cluster.sh
./restore-cluster.sh shoply-cluster.tar.gz      # ← KVM 설치부터 VM 시작까지 자동
```
> cloud-init iso 참조는 스크립트가 자동 제거(`virt-xml --remove-device --disk device=cdrom`)하므로 iso 백업 불필요.

## vs 다른 방법 (비용 포함)

| 방법 | 보관 | 호스트 죽어도? | 복원 시 KVM설치 | 비용 |
|---|---|---|---|---|
| **qcow2 백업 (이 문서)** | **내 PC** | ✅ 부활 | 필요 (스크립트로 자동) | **무료** |
| virsh snapshot | EC2 디스크 | ❌ 같이 사라짐 | — | 무료 |
| EC2 AMI | AWS | ✅ 부활 | ❌ 불필요 (다 박힘) | **월 ~$2.5~3.3** (EBS 스냅샷, 계속) |

→ **무료로 가려면 qcow2 백업 + `restore-cluster.sh`** (KVM 설치 자동화로 AMI의 편함에 근접).
→ 비용 감수하고 **가장 빠른 복원**을 원하면 AMI (KVM 설치 0번). 둘 다 떠두면 최강.

## 요약 흐름

```
1. IP 고정 (DHCP 예약)        ← 안 하면 복원이 깨짐
2. 클러스터 완전 정상화
3. VM 정지 → qcow2+XML 백업 → tar → PC 다운로드
4. (나중에) 새 EC2: KVM 설치 → 업로드 → define+start
5. 호스트IP·DNAT만 갱신 → 끝
```
