## 1. 온프레미스 트래픽 흐름

```
k6 (부하)
  │ HTTP :30080
  ▼
c8i.2xlarge EC2 (공인IP)
  │
  EC2 iptables DNAT                    ← KVM VM은 공인IP 없어 EC2가 포워딩
  │ DNAT → master_VM:30080
  ▼ :30080 (NodePort)
kube-proxy (어느 노드든 Nginx Ingress Pod으로)
  ▼
Nginx Ingress Controller Pod          ← 여기부터 경로 라우팅
  ├── /api/* → API Gateway :4000
  │              ├── /api/products  → Product
  │              ├── /api/inventory → Inventory
  │              ├── /api/orders    → Order
  │              ├── /api/payments  → Payment
  │              └── /api/auth      → User
  └── /     → Frontend :3000
  ▼
PostgreSQL (별도 EC2) · Redis (별도 EC2)
```

### 노드별 서비스 배치 (soft affinity)

```
worker1 (KVM VM)              worker2 (KVM VM)
┌──────────────────────┐     ┌──────────────────────┐
│ Nginx Ingress Pod    │     │ Frontend             │
│ API Gateway   :4000  │     │ Order      :4003     │
│ Product       :4001  │     │ Payment    :4004     │
│ Inventory     :4002  │     │ User       :4005     │
└──────────────────────┘     └──────────────────────┘
  초기 고정, HPA 추가 파드는 노드 꽉 차면 자유 배치
```

---

## 2. 각 컴포넌트 역할

| 컴포넌트 | 역할 |
|---|---|
| **EC2 iptables DNAT** | KVM VM이 공인IP 없어 EC2가 받아 넘기는 **NAT 포워딩**(경로 판단 X). `EC2:30080 → master_VM:30080` |
| **kube-proxy** | NodePort :30080을 모든 노드에 열어줌. 어느 노드로 들어와도 Nginx Ingress Pod으로 라우팅 |
| **Nginx Ingress Pod** | L7 경로 라우팅 — `/api` → Gateway, `/` → Frontend |
| **API Gateway** | 마이크로서비스 분배 (`/api/products` → Product 등) + Prometheus 메트릭 수집 |
| **각 서비스 Pod** | 비즈니스 로직 (ClusterIP, 내부 통신) |

---

## 3. 서비스 간 통신

```
[Order]   ──── POST /reserve ──────→ [Inventory]   (주문 시 재고 예약)
[Payment] ─ 결제성공 → POST /deduct  → [Inventory]   (재고 실차감)
          └ 결제실패 → POST /release → [Inventory]   (예약 해제)
[Payment] ──── PATCH /:id/status ──→ [Order]        (주문 상태 갱신)
```

> 재고 동시성: Inventory가 `SELECT FOR UPDATE`로 행 잠금 → 동시 주문 직렬화 (oversell 방지)

## 4. EKS 트래픽 흐름 (예정)

```
k6 (부하)
  │ :30080 (직접 — 공인IP 있어 NAT 불필요)
  ▼
Worker Node :30080 → kube-proxy
  ▼
Nginx Ingress Pod          ← 온프레와 완전 동일
  ├── /api → API Gateway
  └── /    → Frontend
  ▼
RDS PostgreSQL · Redis
```

→ **EC2 iptables 포워딩 한 단계 없을 뿐, Nginx Ingress부터 백엔드까지 온프레와 완전 동일.**

---

## 5. 온프레 vs EKS 차이 (아키텍처 관점)

| 구간 | 온프레미스 | EKS |
|---|---|---|
| 진입 | EC2:30080 → iptables → VM:30080 | Worker Node :30080 직접 |
| Ingress~서비스 | **완전 동일** | **완전 동일** |
| 노드 | KVM VM 2개 (고정) | EC2 노드 2개 + **Karpenter 자동확장** |
| DB | EC2 PostgreSQL (수동복구) | **RDS Multi-AZ (자동복구)** |

→ 차이는 **진입 앞단(NAT 홉)** 과 **노드 확장·DB 복구** 뿐. 나머지는 같다.

---

## 6. 전체 인프라 배치

```
AWS (ap-northeast-2)

[온프레미스 + 공통]
  c8i.2xlarge EC2  — KVM VM 3개 (master/worker1/worker2) + iptables 포워딩
  PostgreSQL EC2   — 온프레 DB
  Redis EC2
  Monitoring EC2   — Prometheus + Grafana
  k6 (부하 생성)

[EKS — 예정]
  EKS 클러스터 (worker 2 + Karpenter)
  RDS (Multi-AZ)
  Redis EC2
```
