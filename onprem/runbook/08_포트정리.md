## K8s EC2 (호스트 + KVM VM)

| 포트 | 위치 | 용도 | SG 인바운드 소스 |
|---|---|---|---|
| 22 | EC2 호스트 | SSH | 내 IP |
| 30080 | EC2 호스트 | **부하 진입** (iptables DNAT → master VM:30080) | k6 SG |
| 9100 | EC2 호스트 | node_exporter | 모니터링 SG |
| 30080 | master VM | ingress-nginx NodePort (iptables 포워딩 대상) | 내부 |
| 30400 | master VM | gateway 메트릭 | 모니터링 SG |
| 30401 | master VM | product 메트릭 | 모니터링 SG |
| 30402 | master VM | inventory 메트릭 | 모니터링 SG |
| 30403 | master VM | order 메트릭 | 모니터링 SG |
| 30404 | master VM | payment 메트릭 | 모니터링 SG |
| 30800 | master VM | kube-state-metrics | 모니터링 SG |
| 39101 | EC2→worker1 VM | worker1 node_exporter (iptables 포워딩) | 모니터링 SG |
| 39102 | EC2→worker2 VM | worker2 node_exporter (iptables 포워딩) | 모니터링 SG |
| 6443 | master VM | K8s API | 내부 (VM 간) |

> **왜 30080으로 들어오나?**
> - **Nginx Ingress Controller를 NodePort 30080으로 노출** (helm 설치 시 `controller.service.nodePorts.http=30080`).
>   → 외부 부하가 클러스터로 들어오는 **유일한 진입 포트**.
> - NodePort 범위(30000~32767) 중 **30080** 선택 — "80(웹)" 연상이라 기억하기 쉬움.
> - **kube-proxy가 모든 노드에 30080을 열어줌** → 어느 노드(master 포함)로 들어와도 Nginx Ingress Pod으로 라우팅됨.
>   그래서 온프레는 master VM:30080 하나로 보내도 동작.
> - **양쪽 30080 통일:**
>   - 온프레: VM이 공인IP 없음 → `EC2 공인IP:30080 → iptables DNAT → master VM:30080`
>   - EKS: 워커가 공인IP 있음 → `Worker 공인IP:30080` 직접
>   → ALB·Nginx 통로 없이 둘 다 `:30080` 으로 진입 (공정 비교).

# EKS 포트 정리

> EKS 워커는 실제 EC2(공인IP 보유) → iptables 포워딩 불필요. NodePort 직접 접근.

## EKS Worker Node

| 포트 | 용도 | SG 인바운드 소스 |
|---|---|---|
| 30080 | ingress-nginx (NodePort, 웹 트래픽) | k6 EIP |
| 30400~30404 | 앱 prom-client 메트릭 | 모니터링 EIP |
| 30800 | kube-state-metrics | 모니터링 EIP |
| 9100 | node_exporter (DaemonSet, hostPort) | 모니터링 EIP |
| 전체 | 노드 간 통신 (VPC CNI) | Worker Node SG |
| 10250 | kubelet API | Worker Node SG |
| 22 | SSH | 내 IP |

> ALB 미사용 — ingress-nginx NodePort 30080 → k6가 워커 공인IP:30080 직접 타겟
> 온프레미스(EC2:30080 → iptables → VM:30080)와 동일하게 30080으로 진입
> Prometheus 타겟: `<워커1-공인IP>:30400`, `<워커2-공인IP>:30400` ...

## 온프레 vs EKS 메트릭 접근 차이

| | 온프레미스 | EKS |
|---|---|---|
| 워커 노드 | KVM VM (NAT 뒤) | 실제 EC2 (공인IP) |
| 메트릭 접근 | EC2 → iptables DNAT → VM | 워커 공인IP 직접 |
| node_exporter 구분 | 39101/39102 (포트 변경) | 각 워커 공인IP:9100 |
| Prometheus 타겟 | K8s EC2 사설IP | 각 워커 공인IP |
