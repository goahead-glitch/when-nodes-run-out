## 1. 전체 구조

```
AWS (ap-northeast-2)

[온프레미스 + 공통 인프라]
  c8i.2xlarge EC2 (공인IP)
    ├── EC2 iptables 포워딩 (:30080 → VM :30080)
    └── KVM 가상머신 3대 (virbr0 브릿지)
          ├── master   (k8s 컨트롤플레인)
          ├── worker1  (gateway, product, inventory)  ← traffic
          └── worker2  (frontend, order, payment, user) ← order
        k8s v1.34.x

  PostgreSQL EC2  — PostgreSQL 16 (Docker)
  Redis EC2       — Redis 7 (Docker)
  Monitoring EC2  — Prometheus + Grafana
  k6              — 부하 생성
```

| 항목 | 값 |
|---|---|
| 가상화 | **KVM** (중첩 가상화 활성화 후 virt-install) |
| k8s 버전 | v1.34.x |
| CNI | Flannel |
| 이미지 | GHCR `ghcr.io/incheon-soda/shoply-*` |

## 2. 노드별 서비스 배치 (soft nodeAffinity)

```
worker1 (experiment-role=worker1)    worker2 (experiment-role=worker2)
┌────────────────────────┐           ┌────────────────────────┐
│ Nginx Ingress Pod      │           │ Frontend      :3000    │
│ API Gateway   :4000    │           │ Order         :4003    │
│ Product       :4001    │           │ Payment       :4004    │
│ Inventory     :4002    │           │ User          :4005    │
└────────────────────────┘           └────────────────────────┘
```

- **초기 파드**는 지정 워커에 고정 (soft affinity = preferred)
- **HPA 추가 파드**는 노드 꽉 차면 자유 배치
- 배포 시 노드 라벨 필수: `kubectl label node <worker1> experiment-role=worker1`

> 시나리오 3(노드 장애)에서 **worker1을 종료** → 모든 파드가 worker2로 몰려 자원 부족 → Pending.

## 3. 트래픽 진입 — iptables 포워딩 (Nginx·ALB 없음)

KVM VM은 공인IP가 없어 c8i EC2가 **NAT 포워딩** 역할. k6는 EC2 공인IP:30080으로 진입 (ALB·Nginx 통로 없음).

```bash
# EC2:30080 으로 들어온 부하 → master VM:30080 DNAT 포워딩
sudo iptables -t nat -A PREROUTING -p tcp --dport 30080 -j DNAT --to-destination <master-VM-IP>:30080
sudo iptables -t nat -A POSTROUTING -j MASQUERADE
```

> kube-proxy가 master에도 30080을 열어줘서 `EC2:30080 → master VM:30080 → Nginx Ingress Pod`으로 라우팅.
> (Nginx Ingress Controller는 **클러스터 내부 경로 라우팅용**이라 유지 — 외부 통로만 iptables로 단순화)

## 4. 리소스 / HPA 설정 (양쪽 동일)

| 서비스 | request | limit | HPA target | max |
|---|:---:|:---:|:---:|:---:|
| gateway | 100m | 500m | 60% | 6 |
| product | 100m | 500m | 60% | 10 |
| inventory | 100m | 500m | 60% | 10 |
| order | 100m | 500m | 60% | 8 |
| payment | 100m | 500m | 60% | 8 |
| user | 100m | 500m | (HPA 없음) | — |
| frontend | 50m | 200m | (정적) | — |

> request를 작게(100m) 잡아 HPA가 민감하게 발동 → 노드 빨리 참 → Pending 관찰.

## 6. 메트릭 노출 (iptables 포워딩)

KVM VM 내부의 NodePort 메트릭을 외부 Prometheus가 긁으려면 EC2 호스트에서 iptables DNAT 포워딩 필요.

```bash
# 앱 메트릭 (30400~30404), kube-state(30800) → master VM
for port in 30400 30401 30402 30403 30404 30800; do
  sudo iptables -t nat -A PREROUTING -p tcp --dport $port -j DNAT --to-destination <master-VM-IP>:$port
done
# worker node_exporter
sudo iptables -t nat -A PREROUTING -p tcp --dport 39101 -j DNAT --to-destination <worker1-VM-IP>:9100
sudo iptables -t nat -A PREROUTING -p tcp --dport 39102 -j DNAT --to-destination <worker2-VM-IP>:9100
sudo netfilter-persistent save
```
