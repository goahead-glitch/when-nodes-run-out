## 1. PostgreSQL 서버 (DB EC2)

### 설치 (Docker)

> EC2는 user-data(`infra/userdata/postgresql.sh`)로 Docker 설치 + `~/postgres/init` 디렉토리까지 자동 준비됨.
> **compose 파일 + init SQL이 비어있으므로** 아래 scp로 채운다. 전부 `msa_shoply/infra/postgres/` 안에 있는 실제 파일.

```bash
# 맥 → DB EC2 로 compose + init/(schema·seed) + 재고초기화 SQL 한 번에 전송 (scp 한 방)
scp -r -i ~/key/aws-3tier-keypair.pem \
  ~/shopping_k8s/msa_shoply/infra/postgres/docker-compose.yml \
  ~/shopping_k8s/msa_shoply/infra/postgres/init \
  ~/shopping_k8s/msa_shoply/db/load-test-prep.sql \
  ubuntu@<DB-EC2-공인IP>:~/postgres/

# DB EC2 접속 후 실행
ssh ubuntu@<DB-EC2-공인IP>
cd ~/postgres && docker compose up -d
```

# postgre 재고 초기화

docker exec -i shoply-postgres psql -U shoply -d shoply < ~/postgres/load-test-prep.sql

> 실제 compose에는 `max_connections` 직접 지정 대신 `postgres_exporter`(9187)·`healthcheck`·`node_exporter`(host 모드)가 포함되어 있다. (max_connections는 별도 설정 — §설정 포인트 참고)

> 위 scp로 `load-test-prep.sql`도 `~/postgres/`에 같이 들어간다. 실험 전 재고/주문 리셋:
> ```bash
> docker exec -i shoply-postgres psql -U shoply -d shoply < ~/postgres/load-test-prep.sql
> ```
> (상세는 [04_부하테스트.md](04_부하테스트.md) "실험 전 재고 초기화" 참고)

> ⚠️ **max_connections=300** 필수 (파드 다수 × 풀8 합산 대비).

### 설정 포인트

| 항목 | 값 | 이유 |
|---|---|---|
| max_connections | 300 | 커넥션 고갈 방지 |
| 앱 pool max | 8 (서비스당) | 곱셈 폭증 제한 |

## 2. Redis 서버 (Redis EC2)

> EC2는 user-data(`infra/userdata/redis.sh`)로 Docker 설치 + `~/redis` 디렉토리까지 자동 준비됨.
> **compose 파일만 비어있으므로** 아래 scp로 채운다.

```bash
# 맥 → Redis EC2 로 docker-compose.yml 전송 (실제 사용 파일 — redis/redis_exporter/node_exporter 포함)
scp -i ~/key/aws-3tier-keypair.pem \
  ~/shopping_k8s/msa_shoply/infra/redis/docker-compose.yml \
  ubuntu@<Redis-EC2-공인IP>:~/redis/

# Redis EC2 접속 후 실행
ssh ubuntu@<Redis-EC2-공인IP>
cd ~/redis && docker compose up -d
```

> 실제 compose에는 `--maxmemory 256mb --maxmemory-policy allkeys-lru`(캐시 정책), `redis_exporter`(9121), `node_exporter`(host 모드)까지 포함되어 있다.

> Product 서비스만 사용 (상품 목록/상세 캐시). 재고는 캐시 안 함 (실시간 정합성).

## 3. 모니터링 서버 (Monitoring EC2)

### Prometheus + Grafana (Docker)

> EC2는 user-data(`infra/userdata/monitoring.sh`)로 Docker 설치 + `~/monitoring/prometheus` 디렉토리까지 자동 준비됨.
> **compose 파일 + prometheus.yml이 비어있으므로** 아래 scp로 채운다. 전부 `msa_shoply/infra/monitoring/` 안의 실제 파일.

```bash
# 맥 → Monitoring EC2 로 docker-compose.yml + prometheus/(prometheus.yml) 한 번에 전송
# (K8s EC2 사설 IP로 prometheus.yml 타겟 수정 후 — 03_모니터링 참고)
scp -r -i ~/key/aws-3tier-keypair.pem \
  ~/shopping_k8s/msa_shoply/infra/monitoring/{docker-compose.yml,prometheus} \
  ubuntu@<Monitoring-EC2-공인IP>:~/monitoring/

# Monitoring EC2 접속 후 실행
ssh ubuntu@<Monitoring-EC2-공인IP>
cd ~/monitoring && docker compose up -d
```

> 실제 compose에는 `--web.enable-lifecycle`(설정 핫리로드)·`--web.enable-admin-api`(스냅샷 API)도 켜져 있고, Grafana는 `GF_USERS_ALLOW_SIGN_UP=false`로 가입을 막아둔다.

### Grafana 대시보드 import

```bash
# 맥 → Monitoring EC2 로 대시보드 JSON 전송
scp -i ~/key/aws-3tier-keypair.pem \
  ~/shopping_k8s/msa_shoply/infra/monitoring/grafana-dashboard-onprem.json \
  ubuntu@<Monitoring-EC2-공인IP>:~/
```

```
http://<Monitoring-EIP>:3000  (admin / admin1234)
→ DataSource: Prometheus (http://prometheus:9090)
→ Dashboards → Import → Upload JSON file → grafana-dashboard-onprem.json (scp로 전송한 파일 선택)
```

> scrape 타겟 설정 (prometheus.yml) → [03_모니터링.md](03_모니터링.md)

## 4. 부하 서버 (k6)

> EC2는 user-data(`infra/userdata/k6.sh`)로 Docker 설치 + `~/k6/scripts` 디렉토리까지 자동 준비됨.
> apt 설치가 아니라 **`grafana/k6` 이미지를 docker compose로 실행**한다 — compose 파일·스크립트가 비어있으므로 scp로 채운다.
> 전부 `msa_shoply/k6/` 안의 실제 파일.

```bash
# 맥 → k6 EC2 로 docker-compose.yml + scripts/(scenario.js) 한 번에 전송
scp -r -i ~/key/aws-3tier-keypair.pem \
  ~/shopping_k8s/msa_shoply/k6/{docker-compose.yml,scripts} \
  ubuntu@<k6-EC2-공인IP>:~/k6/
```

### 실행 (Prometheus remote write)

```bash
# k6 EC2 접속
ssh ubuntu@<k6-EC2-공인IP>
cd ~/k6

# 환경변수로 타겟·Prometheus 주소 주입 후 실행 (compose가 BASE_URL / PROMETHEUS_RW_URL 참조)
BASE_URL=http://<K8s-EC2-공인IP> \
PROMETHEUS_RW_URL=http://<Monitoring-IP>:9090/api/v1/write \
docker compose up
```

> 실제 compose는 `network_mode: host`로 떠서 k6가 직접 외부로 나간다.
> `command: run --out experimental-prometheus-rw /scripts/scenario.js`로 실행되며, `K6_PROMETHEUS_RW_TREND_STATS=p(50),p(90),p(95),p(99)`로 백분위수까지 Prometheus에 전송한다.
> 결과는 Prometheus remote write로 직접 전송 → Grafana에서 RPS/P95/실패율 확인.
> 스크립트 상세: `msa_shoply/k6/scripts/scenario.js` → [04_부하테스트.md](04_부하테스트.md)
